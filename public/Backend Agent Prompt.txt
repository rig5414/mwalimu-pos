## ARCHITECTURE (BACKEND VIEW)

```
React renderer  →  window.api.*  →  preload.js  →  ipcMain  →  handlers.js  →  SQLite
```

- **contextIsolation: true** — renderer never touches `better-sqlite3` directly
- All handlers use wrapper: `{ ok: true, data }` | `{ ok: false, error: message }`
- New IDs: always `uuidv4()` in main process — **never slug IDs** (`school-uniforms`, `tmp-1`)
- Multi-step writes: `db.transaction(() => { ... })()`
- Table rebuilds / DROP: `PRAGMA foreign_keys = OFF` inside transaction, then re-enable

## CODING STANDARDS (BACKEND)

1. **UUIDs everywhere** for new PKs
2. **No dummy data** in handlers — real SQLite only
3. **Idempotent migrations** — safe to run repeatedly; use `columnExists()` or try/catch ALTER
4. **Re-read `user_version`** after each migration block (or chain version variable)
5. **Category logic** lives in `categoryHelpers.js`, not duplicated in handlers
6. **Minimal diffs** — match existing handler style; no over-abstraction
7. **Friendly errors** — throw messages the UI can toast (e.g. duplicate barcode)
8. **Preserve audit trail** — `stock_movements` logged on stock in/out/sale; don’t bypass

## PRODUCTION DATA SAFETY (MANDATORY)

**Client machines hold real sales, clients, and inventory. Never wipe their DB.**

| Script / action | Safe on production? | Notes |
|-----------------|----------------------|-------|
| `npx electron seed_sample_data.js` | **Yes (default)** | Additive only: inserts missing categories/schools/products; skips duplicates |
| `MWALIMU_SEED_RESET=1` + seed | **NO** | Deletes products, variants, pos_favorites — **dev only** |
| `electron/db/migrate.js` on startup | **Yes** | Idempotent ALTER/CREATE; first-run seed only when no admin user exists |
| `products:delete`, `sales:void` | Use with care | User-initiated; not bulk scripts |

**`seed_sample_data.js` rules (implemented):**
- Does **not** DELETE or UPDATE existing categories, products, clients, sales, users, or stock movements
- `ensureTopCategories()` / `ensureSchoolChildren()` — INSERT only when row missing
- `insertProductIfMissing()` — skip if same name + category_id + subcategory + school_id
- Never run `clearProducts()` unless `MWALIMU_SEED_RESET=1` or `--reset`

**When adding new seed/migration logic:** additive INSERT only; document destructive flags explicitly.
