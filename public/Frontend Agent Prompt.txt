## ARCHITECTURE (FRONTEND VIEW)

```
User → React page/component → window.api.* → (Electron IPC → SQLite)
```

- **All production data** comes from `window.api` — check `if (window.api)` only for dev-without-Electron edge case; never ship dummy inventory/sales.
- IPC responses: `{ ok: true, data }` or `{ ok: false, error: string }` — always check `res.ok` before using `res.data`.
- **Never** `require('better-sqlite3')`, `fs`, or Node APIs in `src/`.
- State: Zustand for auth, cart, POS display mode — keep page-local state for forms/modals.

## DATA MODEL CHANGES YOU MUST RESPECT (DB v3/v4)

These affect how you build UI — **do not revert to old patterns.**

### Category tree (no slug IDs)
- Categories use **UUID** `id` values — never compare to `'school-uniforms'`, `'footwear'`, etc.
- Products attach to **leaf** categories via `category_id`.
- Use `window.api.categories.getLeaves()` for product category dropdowns.
- Use `window.api.categories.getTree()` or `getAll()` (includes `path`, `path_label`) for admin trees.
- School badges: `school_id` → child category under **Schools** root (load from `categories.getAll()`, filter by parent).

### Enriched stock rows (`stock.getAll`, `favorites.list`)
Each variant row may include:
- `category_path` — string array, root → leaf (e.g. `['School Uniforms','Pullovers']`)
- `root_category` — top-level name for POS root folder
- `attributes` — parsed object, e.g. `{ badge: 'plain' | 'badged' }`
- `subcategory` — legacy text, still present; prefer `category_path` for display

### POS hierarchy (linear taxonomy — `src/lib/hierarchyNav.js`)
**Standard categories:** `[Category → Subcategory → Product → Variant]`  
**Schools / LCA:** `[Schools → Londiani Christian Academy → Primary | Junior Secondary → Product]`  
**Other schools:** `[Schools → School name → Product]`

- Browse logic: `computeBrowseState(filteredStock, path, search)`
- Tree sidebar: `HierarchyTreeSidebar.jsx` — **branches default collapsed** (`expandedNodes` empty until user expands)
- Breadcrumbs on cards: `getDisplayBreadcrumb(row)` (e.g. `Schools › LCA › Primary`)
- Do not hardcode `CATEGORY_SUBCATEGORIES` in new POS code — taxonomy constants live in `hierarchyNav.js` (`SUBCATEGORIES_BY_PARENT`, `SCHOOL_BRANCH_ORDER`, etc.)

### Legacy column
`products.subcategory` still exists in DB but is synced from leaf category — UI should use leaf `category_id` + path labels, not a separate subcategory field (Products page already updated).

## `window.api` QUICK REFERENCE

Use **exact method names** from `preload.js`:

```javascript
// Categories
window.api.categories.getAll()
window.api.categories.getTree()
window.api.categories.getLeaves()
window.api.categories.create({ name, parent_id, icon, sort_order })
window.api.categories.update({ id, name, parent_id, icon, sort_order })
window.api.categories.delete(id)

// Products
window.api.products.getAll({ include_inactive: true })
window.api.products.getById(id)
window.api.products.create({ name, category_id, school_id, price, variants, ... })
window.api.products.update({ id, ... })
window.api.products.importMapped({ rows, default_category_id })

// Stock, sales, reports, favorites, print — see preload.js
```

**Common mistake:** `categories.list()` / `products.list()` do **not** exist — use `getAll`.
