🏗️ ARCHITECTURE
Tech Stack
- Frontend: React 18 + Vite + HashRouter + Zustand
- Desktop: Electron 29
- Styling: Tailwind CSS v3
- Charts: recharts
- Database: SQLite (better-sqlite3), WAL mode, foreign_keys ON
- IPC: window.api (contextBridge)
- Thermal: node-thermal-printer (EPSON-style default)
- IDs: uuid v4 for all primary keys (categories, products, variants, users, sales, …)
- Icons: Image uploads (BLOB) with emoji fallback

Category model (scalable tree)
- **Root** categories: School Uniforms, Games Attires, Footwear, Inner Wear, Beddings, School Bags, Schools.
- **Subcategories** under roots: Pullovers, Shirts, Toughees, etc. (admin can add more at any depth).
- **Schools** under Schools root: Londiani Christian Academy (+ Primary/Junior Secondary phases), Londiani Girls, etc.
- Products assign to a **leaf** category_id; optional school_id for badged items.
- **Icons:** Now image-based (icon_data BLOB), with emoji string fallback for legacy categories.
- POS path: `[root, sub, Plain|Badged, productName]` built from `category_path` + variant attributes.

📝 CODING STANDARDS
1. No Dummy Data: All production pages MUST use `window.api`. Fallbacks are for browser dev mode ONLY.
2. Async/Await: Use modern async patterns for all IPC calls. Handlers return `{ ok, data }` or `{ ok: false, error }`.
3. UUIDs: Generate `uuidv4()` in the backend for ALL new records. Never use slug/human-readable IDs.
4. Transitions: Wrap multi-step DB writes in `db.transaction(() => { ... })()`.
5. Categories: Assign products to **leaf** categories. Use `categories:getLeaves` or `resolveProductCategoryId()` — do not hardcode taxonomy in UI.
6. Table rebuilds: If dropping columns, use `PRAGMA foreign_keys = OFF` inside a transaction (see v4 UUID migration pattern).
7. Images: Store in `icon_data` BLOB; serve via IPC as data URLs. Validate file size (<5MB), MIME type (image/jpeg, image/png).
